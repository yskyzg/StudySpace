## 这是什么

StudySpace 由单文件番茄学习站 Study-WR 重构而来，目标是做成一台能装进手机、长期使用的学习工具，而不是演示页面：

- **打开就是空状态**：没有预设科目、没有演示数据，科目、目标与计划都由自己建立。
- **离线优先**：不需要账号，不上传学习记录，不接云端数据库；主数据 + 影子备份双写，刷新、息屏、重启都不丢。
- **单文件应用**：`index.html` 内含全部 HTML / CSS / JS，零前端框架、零外链、无构建步骤；Capacitor 只负责原生外壳与系统能力。
- **视觉**：澄净宣纸浅色主题（黛蓝 / 朱红 / 竹青 / 藤黄 + 暖纸底），圆角四档、双层阴影、纸面纹理统一为设计令牌。**不提供深色模式**。
- **隐私**：无埋点、无追踪；API Key 只在本机配置，AI 请求直连你填的接口。

详细产品范围见 [PRD_番茄学习助手_APK重构.md](PRD_番茄学习助手_APK重构.md)；功能分布与口径见 [功能设计清单.md](功能设计清单.md)；视觉细则见 [界面与交互设计规格.md](界面与交互设计规格.md)。

## 关键规则

**打卡判定**：当天有真实专注记录（时长 > 0，App 内计时或补记都算），或当天计划已勾选完成，二者满足其一即打卡。只设了计划、或点过「开始专注」但没落下记录，都不算；取消完成后该项立即不再支撑打卡。来源标记只供清理数据时按类撤销，残留标记不会误判。达到日目标额外标红为「达标」，今天还没学不算断签。

**计划完成率**：默认「总计划完成率」＝过去未完成累积到今天 + 今日计划，含今天补完的逾期计划，过去就完成的不进总口径；可切「今日计划完成率」＝仅今日计划。两口径都排除已归档计划及其未完成快照，按**完成条数 ÷ 统计条数**计算，完成一项涨一档，与专注分钟无关。口径选择保存在本机。

**计划 ↔ 番茄钟**：首页任务、计划页任务、月历当日详情都有「去专注」——点一下跳到专注页、带入科目并绑定计划，**不会自动开始计时**；倒计时按计划「预计时间」预设（1~180 分钟，没填沿用原设置），可改、可切正计时，什么时候开始由你定。关联计划下拉只列当前科目的未完成计划，换科目跟着变，也可不选。倒计时到点或点「结束并记录」时，关联计划自动打勾、已专注分钟累加，会话留下 `planId` / `planTitle`。计时中或有未结束进度时不能再从别的计划改绑，弹窗要求先「结束并记录」或「重置时长」。

**错题复习**：按 **1 → 3 → 7 天**排下次复习，之后每 7 天循环；到期进「待复习提醒」。点过一次后仍可在详情点「再复习一次（提前重做）」重新计时。编辑错题保留复习历史。

**复盘范围**：每日只汇总所选当天；每周汇总截至所选日期的最近 7 天。弹层摘要与 AI 请求用同一范围。已写复盘在计划月历左上角显示「日」（朱红）或「周」（紫檀）徽标，点日期详情显示「已每日复盘 / 已每周复盘」并可打开编辑。

**归档**：归档整理只搬今天及以往**已完成**的日常计划与已完成的长期计划；以往未完成的欠债不被归档。归档保存完整快照，计划月历和当日详情仍能看到每天的计划，可改完成状态或恢复。归档页支持年／月两级筛选与「全部归档」视图。

**计时与通知**：计时基于时间戳，息屏、切后台、重启按真实流逝补齐，结束按秒记录（≥1 秒）。开始专注挂常驻通知，到点另弹独立「专注完成」通知；15 分钟、最后 5 分钟（大于 1 小时的倒计时）各有独立提醒。屏幕常亮默认开启，可在计时设置关闭；原生用 Capacitor KeepAwake，浏览器降级 Wake Lock，申请失败只降级、不影响计时。常亮会增加耗电与发热。

**界面交互**：说明文字统一收成 `ⓘ` 图标，点击展开、点别处或滚动收起；同类操作重绘保持当前页面与滚动位置，切页才回顶；重开 App 恢复上次页面、滚动与分组折叠状态。轻提示为暖纸卡，普通提示约 2.8 秒、完成提醒约 4.2 秒自动消失，长计划名与时长会折行不溢出。

## 浏览器预览

直接用浏览器打开 `www/index.html` 即可，无需安装依赖。也可起一个静态服务：

```bash
python -m http.server 8080
# 浏览器访问 http://localhost:8080
```

浏览器环境下，系统通知、原生文件导出／分享、原生 HTTP 会走降级路径或不可用，完整体验以 APK 为准。

## 安装与覆盖更新

1. 在 GitHub Actions 页面下载 `StudySpace-APK` 构建产物，解压得到 `app-debug.apk`。
2. 传到手机安装（需允许「未知来源」）。
3. 后续更新直接安装新 APK 即可覆盖，**数据会保留**。

> 新 APK 使用仓库内 `android.keystore.b64` 固定签名，`appId` 始终为 `com.studywr.pomodoro`，`versionCode` 随构建递增。
> 若手机上装的是固定签名方案之前的旧包，首次升级仍需「导出备份 → 卸载旧包 → 装新包 → 导入备份」。这一次之后即可无损覆盖。
> 请勿删除 `android.keystore.b64`，也不要改 `capacitor.config.json` 里的 `appId`。

零基础逐步说明见 [打包APK操作手册.md](打包APK操作手册.md)。

## 数据与隐私

- 学习记录、设置、AI 会话与 API Key 只存在你手机/浏览器本机，仓库里不包含任何个人数据。
- 主数据键为 `studywr_app_v1`，影子备份 `studywr_app_v1_bak`，另有界面状态、折叠状态与计时状态独立存储。
- 主槽损坏时自动从影子备份恢复；双槽都损坏时保留原始数据不覆盖。
- 「导出备份（JSON）」通过系统分享保存到本机 Documents；重要数据建议定期备份。
- 仓库是公开的：**不要把真实 API Key 写进代码文件上传**，只在本机 App 的「设置 → AI 接口」里填写。
- 本地存储不是加密保险箱，仅适合个人设备使用。

## 打包 Android APK

推送到 `main` / `master` 分支后，GitHub Actions 的「构建安卓 APK」自动运行，也可在 Actions 页面手动 `Run workflow`：

1. 等待构建出现绿色对勾；
2. 在该次运行页底部 `Artifacts` 下载 **`StudySpace-APK`**；
3. 解压安装 `app-debug.apk`。

流程内部会自动准备 `www/`、安装依赖、生成图标、写入版本、重新生成 Android 工程、配置固定签名并输出 APK 签名指纹供核对。

**改版本号只改一处**：`www/package.json` 的 `version`。构建时会同时写入 App 内 `APP_VERSION` 与 Android `versionName`，任何一边没写进去都会让构建失败，避免发出版本对不上的包。App 内关于页还会向原生回读真实版本与 Build 号。

如需本机打包，先安装 Android SDK，再在 `www/` 目录执行：

```bash
npm install
npm run build:apk
```

## 项目结构

仓库采用扁平结构，StudySpace 文件直接位于根目录：

```text
./
├── index.html                    应用全部代码（单文件 HTML/CSS/JS）
├── package.json                  Capacitor 依赖、脚本、版本单一来源
├── capacitor.config.json         appId / appName / webDir / 插件配置
├── android.keystore.b64          固定签名密钥（勿删）
├── assets/logo.svg               图标与启动图源图
├── .github/workflows/build-apk.yml
├── README.md                     本文件
├── 功能设计清单.md
├── PRD_番茄学习助手_APK重构.md
├── 界面与交互设计规格.md
└── 打包APK操作手册.md
```

构建时 workflow 会先 `mkdir -p www && cp index.html www/index.html`，再交给 Capacitor 生成 Android 工程。

## 开发约定

- 改动只涉及应用源码与项目文档，不动根目录旧档案与本地工具目录。
- 保持单文件零依赖：不引入框架、构建工具、CDN 外链或远程字体。
- 不新增深色模式；不恢复演示数据；不恢复 AI 外链工具。
- 小步精准修改，只动与需求直接相关的代码与文档。
- 修改 `index.html` 后至少做：内联脚本语法检查、相关交互专项验证、390px 视口目视检查长文本与弹层。
- 不要自动提交或推送，除非明确要求。
